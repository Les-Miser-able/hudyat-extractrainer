FSL training lab / Lesson 01

Teach your model
two hand poses.

Your first win: train one practice category that distinguishes an open palm from a closed fist, then try a new image.

About 8 minutes to read and answer · Collection and training take additional time.

The idea

You supply examples. The model learns the difference.

A category is one model. A class is one gesture label inside that model. Our category is practice; its two classes are open_palm and closed_fist. These are practice labels, not FSL translations.

  1. ImagesYour original examples
  2. LandmarksDetected hand points
  3. 32 × 128One prepared sequence
  4. TrainConv1D + BiLSTM
  5. Class labelWhich pose fits best?

Preparation extracts hand coordinates and creates splits. Training adjusts the classifier using the training split. Your model reads landmark sequences, rather than image pixels directly.

Sources: this trainer’s input pipeline and MediaPipe’s landmark outputs.

Recall: what belongs inside data/practice/ for this exercise?

01 / Collect

Make each file a separate example.

Create this layout in your project. The files below are examples to record yourself; the lesson does not create training images.

data/
  practice/
    open_palm/
      capture01.jpg
      capture02.jpg
      capture03.jpg
    closed_fist/
      capture01.jpg
      capture02.jpg
      capture03.jpg

Take a new photo for each file. Reposition your hand between captures, keep fingers and wrist in view, and keep the camera’s mirroring consistent. Use the same intended pose within each class.

Three independent source groups per class is this trainer’s minimum. It is enough to exercise the pipeline, but far too little to establish reliable recognition. Copied files, jitter variants, or neighboring frames from one recording do not become independent recordings.

This first exercise uses still poses. For a moving gesture, use a video containing the complete movement; a photograph cannot capture its trajectory. The trainer maps recordings to 32 timesteps. Each timestep has 128 features: 63 left-hand coordinates, 63 right-hand coordinates, and two presence flags.

Source: category requirements, input layout, and independent source groups.

Recall: one original photo produces eight jitter variants. How many original sources is that?

02 / Prepare

Turn recordings into a dataset.

Start the dashboard with the Python environment that has requirements.txt installed:

python dashboard.py
  1. Open Datasets in FSL Studio.
  2. Set Source root to data and Dataset root to datasets_lesson1, then click Scan folders.
  3. Select practice, leave the preparation settings at their defaults, and click Prepare dataset.
  4. Read Activity. Continue only when the job is Completed.

Use a new dataset-root name if that output already contains data. Preparation preserves existing outputs.

Prefer the terminal? Run this from the project root.
python categories.py prepare --category practice --datasets datasets_lesson1

The default targets are 70% training, 15% validation, and 15% test, split by source group before augmentation. With only three groups per class, the requirement for nonempty splits means one group goes into each split; the percentages cannot hold exactly.

If extraction rejects your recordings, inspect extraction_report.json in the output or the reported extraction-failed report. A detectable hand is required. Add genuinely new examples rather than duplicating rejected files.

Source: extraction and failure reports and split rules.

03 / Train

Start one small practice run.

In Training, choose practice, name the run lesson01, and set Epochs to 20. Keep batch size 32, learning rate 0.001, and patience 12. This is an exercise configuration, not a guarantee of convergence or accuracy.

Check that the displayed dataset root is datasets_lesson1, then click Start training. An epoch is one pass through the training data. Early stopping may finish before epoch 20.

Equivalent terminal command
python categories.py train --category practice --datasets datasets_lesson1 --run lesson01 --epochs 20

After completion, open Model runs. The checkpoint is runs/practice/lesson01/best.keras; labels are in classes.json. Use a fresh run name for another experiment.

04 / Test

Give it a genuinely new image.

Take another open-palm photo after dataset preparation. Save it outside the training-source category, for example evaluation/practice/open_palm/new.jpg.

  1. Open Try a prediction.
  2. Select practice / lesson01.
  3. Enter the new image’s project-relative path and click Recognize sample.
  4. Compare the predicted label with the pose you actually recorded. Repeat for the closed fist, including errors in your observations.
Equivalent terminal command
python trainer.py predict --run runs/practice/lesson01 --sample evaluation/practice/open_palm/new.jpg

A correct result is a useful first win; one correct image does not establish general accuracy. This classifier chooses among trained classes. It does not automatically know every other gesture or acquire new labels when you add source files. Adding a class requires preparing and training a model that includes it.

Recall: what is the most useful next check after a successful run?

Your stopping point

  • I can point to the category folder and its two class folders.
  • I can explain why three copied photos do not supply three independent sources.
  • Preparation and training completed, or I can show the exact stage and error where they stopped.
  • I located the saved checkpoint and tried an image that was not prepared with the dataset.

Before your next session: without rereading, explain the difference between preparation and training. Tell your teacher what the new image predicted and which step was hardest. We will use that evidence to choose the next lesson.

Ask follow-up questions here at any point. If a command fails, share its Activity output; there is no need to guess which setting to change.
