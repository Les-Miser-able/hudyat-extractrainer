FSL training lab / Lesson 02

From a gesture video to training data.

Your win: prepare a small category of video clips, locate its landmark sequences, and check what extraction accepted.

About 6 minutes · Requires the project's Python ML environment · Run commands from the repository root

Understand

The video path already exists.

  1. Video clipOne complete gesture
  2. DecodeOpenCV reads all frames
  3. LandmarksMediaPipe tracks two hands
  4. SequenceT frames × 128 features
  5. Prepare32 frames × 128 features

Each frame stores 21 XYZ points per hand and two hand-presence flags: 63 + 63 + 2 = 128 values. A missing hand has zero coordinates and a zero flag. The extractor starts a fresh VIDEO detector for every clip and supplies increasing frame timestamps.

Preparation interpolates landmark coordinates to 32 timesteps. Presence flags use nearest-frame selection, and absent-hand coordinates are zeroed. By default a video produces one prepared sequence; the repeat-and-jitter setting applies to static inputs. Optional timing augmentation can add training samples. There is no additional centering or hand-size normalization.

Project sources: video extraction and resample / prepare. Primary reading: MediaPipe video mode and landmark coordinates.

01 / Prepare the recordings

One clip, one gesture.

Trim each recording to one complete gesture with little unrelated lead-in or trailing footage. Keep hands visible and use consistent orientation and mirroring. These are preparation choices: the current code processes the entire clip and does not segment gestures or trim idle time automatically.

Supply constant-frame-rate footage. The code calculates timestamps from frame index and reported FPS; it rejects invalid FPS but does not establish that a file is truly constant-rate. Supported extensions are .mp4, .avi, .mov, .mkv, .webm, and .m4v, subject to the installed decoder.

Optional: trim and convert with FFmpeg

If FFmpeg is installed, this example takes three seconds beginning at second two and writes a 30-FPS clip. Adjust the interval to your complete gesture; 30 FPS is an example, not a trainer requirement. Keep the original recording outside the source folder so both copies are not prepared.

ffmpeg -ss 00:00:02 -i recording.mp4 -t 3 -vf "fps=30" -an clip_cfr.mp4

The official FFmpeg fps documentation explains that conversion duplicates or drops frames to produce a constant frame rate.

For a small functional exercise, use at least two gesture classes and three independent accepted source groups per class. More examples are needed to assess recognition quality. Put each clip under its gesture label:

data/practice_video/
  gesture_one/
    recording01.mp4
    recording02.mp4
    recording03.mp4
  gesture_two/
    recording01.mp4
    recording02.mp4
    recording03.mp4

The names above are placeholders. Choose the actual labels you intend to recognize.

Three overlapping clips from one recording are still one source group. When clips share a recording, session, or signer that must remain together, supply explicit group IDs using --groups-dir. Default filenames do not infer those relationships.

02 / Run preparation

Let the project extract and preprocess.

python categories.py prepare --category practice_video --dataset-name video_v1
python trainer.py inspect --dataset datasets_augmented/practice_video/video_v1

Use the Python environment with requirements.txt installed. If needed, install into that same environment with python -m pip install -r requirements.txt. The detector asset is models/hand_landmarker.task; the default asset downloads if missing.

Choose a fresh dataset name if this output already exists. The command extracts original-length landmarks, separates source groups into train/validation/test, resamples videos, and validates the prepared arrays. It preserves the original video files.

Dashboard route: start python dashboard.py, open Datasets, set source root to data and dataset root to datasets_augmented, scan, select practice_video, set Dataset name to video_v1, and click Prepare dataset, followed by Validate dataset.

03 / Check the evidence

Accepted does not mean well detected.

Inside datasets_augmented/practice_video/video_v1/What to inspect
extraction_report.jsonAccepted/rejected files; compare detected_frames with frames for each accepted video
extracted/<class>/<id>.npyOriginal-length landmarks, shape (T,128)
extracted_sources.jsonMapping from extracted IDs to original source paths
{train,validation,test}/<class>/*.npyPrepared training samples, shape (32,128)
manifest.json / preprocessing.jsonSource groups, split assignments, and saved extraction settings

The extractor rejects unreadable videos, invalid FPS, fewer than two decodable frames, early termination relative to the declared frame count, and videos with no detected hand anywhere. A clip with only a few detected frames can still be accepted; review that clip before trusting it. A failed preparation writes a timestamped extraction-failed report beside the requested output folder.

Optional: add timing variations

python categories.py prepare --category practice_video --dataset-name video_augmented_v1 --video-extra-samples 3 --video-time-warp 0.05

This keeps the original prepared sample and requests up to three extra timing variations for each training video or multi-frame landmark source. Validation/test videos and static-image behavior stay unchanged. A strength of 0.05 limits the timing shift to 5% of the clip timeline; the full movement and its order are retained. Motionless clips may generate fewer distinct samples; check video_augmentation_report.json for actual counts and reasons. Zero extra samples disables this feature. The dashboard has the same Extra samples and Timing strength controls.

See the video augmentation guide. These variants add training examples, not independent recordings.
