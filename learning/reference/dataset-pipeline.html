What do the controls do?

In the lesson, the three dropdowns change an illustrative example: source type, assigned split, and requested timing extras. Changing them updates the predicted sample count immediately. The round quiz choices select one answer; Check my recall gives feedback. These teaching controls do not start project jobs.

In FSL Studio, controls configure real jobs. A checkbox enables an option; several source-folder checkboxes can be selected together. A dropdown chooses one item. The preparation values are numeric fields: type a value or use their small up/down arrows.

What each stage does.

1. Organize and select sources

data/colors/blue/S1/clip.mp4 means category colors, gesture label blue, and optional source folder S1. Every category trains an independent model. A recording should represent one intended gesture; preparation does not label or automatically trim it for you.

All source folders and supported file types are the default. Choose source folders beneath each gesture, or Videos only. Selected folders are searched recursively. Files directly inside a gesture are excluded when choosing specific subfolders. Gesture classes without matching files are omitted when a filter is active; at least two populated classes must remain.

For an all-.npy input without filters, the low-level preparation path reads arrays directly inside each gesture folder. For nested .npy-only inputs, explicitly choose the relevant source folders. Media preparation searches recursively. This distinction matters when dashboard discovery counts more arrays than unfiltered direct-array preparation loads.

source_files / folder_selection and prepare.

2. Choose a new named output and pass safety checks

New datasets are saved to datasets_augmented/<category>/<custom name>/, or the same pattern beneath another dataset root. Name is editable in the dashboard; CLI preparation uses --dataset-name and defaults to prepared_v1. Existing nonempty outputs are not overwritten. Input and output must be separate, non-nested folders; dashboard paths must stay inside the project.

Older datasets directly in a category folder remain selectable as Original dataset. The CLI can choose those explicitly with --dataset-name . when training. With multiple versions, select a specific version rather than assuming the system chooses the newest one.

Named and original dataset discovery, dashboard routing, and CLI routing.

3. Extract original-length landmarks when media is present

Images are EXIF-oriented and converted to RGB before IMAGE detection. A detected image produces one frame. Videos are decoded by OpenCV and processed with a fresh VIDEO detector per clip; all decoded frames are retained. Timestamps are calculated from frame index and reported FPS and made strictly increasing. Supply constant-frame-rate footage: the code checks FPS but does not prove a video is constant-rate.

There is no automatic gesture segmentation, idle trimming, horizontal flip, or spatial crop in this preparation path. A whole clip becomes one original landmark sequence. Compatible .npy files already contain landmarks and skip detection; mixed media input can include them too.

Unusable media is recorded as rejected. Unsupported extensions are ignored and reported in media preparation. Same-label duplicate landmarks are rejected; identical data with conflicting labels aborts media preparation. Existing-array-only preparation rejects duplicate source data rather than treating copies as new independent inputs.

Extractor.extract / prepare_media. Primary documentation: MediaPipe execution modes and timestamps.

4. Pack and validate the landmark representation
Columns 0–62:    left-hand 21 × XYZ
Columns 63–125:  right-hand 21 × XYZ
Column 126:      left hand present?  0 or 1
Column 127:      right hand present? 0 or 1

Slots follow reported handedness, not detector list order. Swap hands exchanges slots without mirroring coordinates. When both detections claim the same hand, the higher-confidence one fills the slot. Missing hands keep zero coordinates and a zero presence flag; missing-hand frames inside a video are retained.

The extractor uses MediaPipe image landmarks, not world-coordinate landmarks. X and Y are normalized to image width and height; Z is wrist-relative at roughly X's scale. The project adds no centering or hand-size normalization. Existing arrays must already follow the expected convention.

Existing arrays accept (128,) or (T,128) with T ≥ 1. The loader converts to float32 and checks real finite numbers, binary presence flags, zero coordinates for absent hands, and at least one present hand somewhere in the source.

pack_result, load_sequence, and Google's coordinate definitions.

5. Identify related sources, then split whole groups

For direct arrays, the default group is the original relative source path. The media route groups Roboflow .rf. filename siblings by their inferred original stem. These defaults do not establish signer/session independence. For related recordings, use an explicit Group CSV: --groups-dir groups reads one category CSV, while low-level trainer.py prepare --groups file.csv reads a single file.

path,group
blue/S1/clip01.mp4,signer_01
red/S1/clip02.mp4,signer_01
blue/S2/clip01.mp4,signer_02

This is a partial illustration, not a complete usable CSV. Supply every selected supported source exactly once and enough groups covering every gesture. Source-folder selection does not assign groups.

The minimum is two classes and three accepted independent groups per class. For class-local groups, the code shuffles per class, rounds the requested validation/test group counts, and leaves a training remainder with all three splits nonempty. For shared signer/session groups across classes, it searches for a group-disjoint assignment covering every class in each split. It can fail when no suitable assignment is found.

The default target fractions are 70/15/15, but group sizes and integer rounding alter the result. With three class-local groups per gesture, each split receives one. With ten per gesture and defaults, six groups train, two validate, and two test.

split_sources, default_group / prepare_media. For the reason behind group isolation, see scikit-learn's primary explanation; this code uses its own implementation.

6. Turn every accepted source into fixed-length samples

One-frame input: repeat the pose to 32 rows and add independent Gaussian noise to present-hand coordinates at each timestep. Default variants = 8, jitter standard deviation = 0.0075. Flags stay binary and absent-hand coordinates stay zero. These are synthetic examples of a held pose; a photograph does not acquire a real recorded motion.

Multi-frame input: linearly interpolate coordinates across the full source to 32 timesteps. Flags use nearest-frame selection, followed by zeroing absent slots. Ninety frames → one 32-step sequence by default. Thirty-two is a timestep count, not 32 FPS or 32 seconds.

Static behavior is split-wide: static repeat-and-jitter generation also occurs for sources assigned to validation or test. The source groups remain disjoint, but these evaluation samples are synthetic versions of their held-out static originals.

synthetic_sequence / prepare and resample.

7. Optionally add training-only video timing variations

Extra samples defaults to zero. Set it to 3 to request up to three additional samples for each training video or multi-frame array. Timing strength defaults to 0.05: interior positions move by at most 5% of the normalized clip timeline. Endpoints and movement order are preserved; the code creates landmark arrays, not modified video files.

Validation/test multi-frame sources keep their single base sample. Static sources retain their existing repeat-and-jitter behavior. Duplicate or invalid candidates are discarded, so motionless or sparse sequences may produce fewer than requested extras. Inspect actual counts and shortfall reasons in video_augmentation_report.json.

A dataset version name such as augmented_v2 does not enable these transformations. The settings do. The same source group's assignment is retained by every variation.

configuration / augment_sequence and Accepted option ranges.

8. Save artifacts, restore provenance, and validate

Prepared files are float32 .npy arrays under split/gesture folders, with hashed filenames. The manifest links each generated path to its label, original source, group, split, variant identity, and whether it is synthetic. Preprocessing metadata records the recipe.

Media extraction stages temporary arrays, runs the common preparation code, then restores original source names in the manifest and video augmentation report. It saves original-length arrays under extracted/ and their source mapping, records detector settings and model hash, and performs final validation. Temporary extraction files are cleaned up; originals are left in place.

Validation checks shapes, finite coordinates, presence rules, manifest/file agreement, every class in every split, and isolation of groups, sources, and variant identities. It does not prove that labels are correct or that accepted hand tracking is visually good.

inspect_dataset / save_augmentation_summary and prepare_media.

9. Train from the chosen version, then predict consistently

Preparation ends before classifier training begins. The training job receives the selected version's exact path, validates or loads its packed cache, and saves a separate run under runs/category/run-name. A packed cache is built when needed by training, not automatically by preparation; each version has its own _training_cache directory.

The run records the dataset argument in training_config.json, copies preprocessing.json and the split manifest, and saves the checkpoint and class order. File prediction uses the selected run. Raw-media prediction checks the stored extraction settings and landmark-model hash; normalized-array prediction uses the same fixed-length sampling. Inference adds no preparation jitter or timing augmentation.

open_cache and train / predict.

Read one manifest row.

{
  "path": "train/blue/<hashed-id>_000.npy",
  "source": "blue/S1/clip01.mp4",
  "label": "blue",
  "group": "signer_01",
  "split": "train",
  "variant": 0,
  "variant_of": "blue/S1/clip01.mp4",
  "static": false,
  "synthetic": false
}

Illustrative fields, not an actual recording or a complete copied row. This says: the prepared path represents blue, comes from this video, belongs to an explicitly assigned signer group, and is the base resampled sequence. A timing extra retains source/group/split but has a later variant number, synthetic = true, and augmentation details. An image's generated repeat-and-jitter samples have static = true and synthetic = true.

What can stop preparation?

  • Missing or empty sources, fewer than two classes, or fewer than three accepted independent groups per class.
  • A reused nonempty output folder, invalid dataset name, or overlapping source/output directories.
  • Invalid array shape, NaN/infinity, nonbinary flags, absent-hand coordinates that are not zero, or no hand in the entire sample.
  • Unreadable media, invalid FPS, too few video frames, early decode termination, or no detected hand anywhere.
  • Duplicate/conflicting source data, an incomplete Group CSV, or no suitable group-disjoint split with every class represented.

Some raw-media failures reject individual sources and continue. If too few acceptable groups remain, the whole preparation still fails. Review the report rather than counting original files alone. Failed media preparation writes a timestamped <dataset-name>.extraction-failed-....json beside the output. Partial outputs may remain; use a fresh version name for a retry.

Keep these terms separate.

Category
One independent classifier task, such as colors.
Gesture / class
A label inside the category, such as blue.
Source recording
An original image, clip, or supplied landmark file.
Landmark sequence
Detected hand positions ordered over time, following the project's left/right/presence layout.
Source group
Related sources that must stay together when splitting; consistent with the project's glossary.
Prepared sample
One 32 × 128 array consumed by the classifier.
Augmented sample
A synthetic variation that preserves the source gesture's label and identity.
Dataset version
A named collection of prepared samples plus its manifest and preprocessing recipe.
Training run
A separate attempt to learn model weights from one selected prepared dataset.
